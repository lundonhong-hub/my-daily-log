# 뉴스레터 파이프라인 재설계 — 변경 요약

> 이 문서는 참고용입니다. 레포에 넣을 필요 없습니다.

## 0. 구조 변경 한 줄

**LLM이 HTML을 만들던 구조 → 파이썬이 HTML을 만들고 LLM은 뉴스 텍스트만 채우는 구조.**

| 항목 | 기존 | 변경 후 |
|---|---|---|
| Haiku 역할 | HTML 전체 생성 (CSS 포함) | JSON 텍스트 필드만 |
| Haiku 출력 | 약 10,600 토큰 | 약 700 토큰 |
| Haiku 입력 | 시장 JSON 전체 + 14,900자 템플릿 | 시세 한 줄 요약 + 1,900자 프롬프트 |
| 수치·요일·정렬 | Haiku | 파이썬 |
| 검증 | 없음 | 저장 전 자동 검증, 실패 시 중단 |
| 발송 | 네이버 메일 | 텔레그램 (요약 + HTML 첨부) |
| 레포 파일 수 | 5개 | 5개 |

출력 토큰이 입력 토큰보다 비싸므로 **월 비용은 유지가 아니라 하락**합니다.

## 1. 파일 구성

기존과 같은 **5개 파일**입니다. 전부 레포 루트에 둡니다.

```
data_collector.py                수집 + 파생지표 계산 + 리스크 판정 + 알림 생성  (522줄)
generate_dashboard.py            렌더 + 검증 + 텔레그램 + 오케스트레이션        (720줄)
dashboard_template.html          레이아웃 + CSS (기존 디자인 그대로)
prompt.md                        LLM 프롬프트. 일요일 구간은 [[IF_SUNDAY]] 마커로 분기
.github/workflows/dashboard.yml
```

`generate_dashboard.py` 안은 5개 구역으로 나뉩니다 —
① 렌더링 ② 산출물 검증 ③ 텔레그램 ④ LLM 호출 ⑤ 메인.

`prompt_template.md`, `prompt_template_weekday.md` 는 삭제합니다.

## 2. 수정한 버그

### B1. 요일 라우팅이 하루 밀려 있었음
`generate_dashboard.py` 의 `datetime.now()` 가 UTC로 동작했습니다.
러너 TZ가 UTC인데 yml의 `export TZ='Asia/Seoul'` 은 해당 셸 스텝에만 적용됩니다.

- KST 일요일 발행분 → UTC 토요일 실행 → 평일 프롬프트
- KST 월요일 발행분 → UTC 일요일 실행 → **일요일 프롬프트(트렌드 레이더)**

즉 일요일 편집본은 일요일에 한 번도 나간 적이 없습니다.

**수정**: `datetime.now(ZoneInfo("Asia/Seoul"))` + 워크플로 job 레벨 `env: TZ: Asia/Seoul`.

### B2. 웹검색 결과가 모델에 전달되지 않았음
```python
tool_results.append({..., "content": "검색 완료"})   # 삭제됨
```
검색 결과 자리에 "검색 완료" 네 글자를 넣고 있었습니다.
뉴스·수급·경제일정 섹션 전체가 모델의 창작이었습니다.
(CME FedWatch 82%, 외국인 4조1914억, "파키스탄 미중 휴전 중개 론" 등)

**수정**: 서버측 검색은 `stop_reason == "pause_turn"` 으로 되돌아옵니다.
assistant 메시지를 그대로 이어 붙여 재요청하는 정상 루프로 교체.
추가로 프롬프트 R5에서 **source URL이 없는 항목은 폐기**, `_issue()`/`_trend()` 가 코드로 강제합니다.

### B3. 잘린 HTML을 검증 없이 커밋·발송
`if "</html>" in html:` 이 거짓이면 그냥 통과했습니다.
`stop_reason` 은 출력만 하고 검사하지 않았습니다.

**수정**: `stop_reason != "end_turn"` 이면 예외.
`validate_html()` 을 저장 **직전에** 호출, 실패 시 종료코드 1 → 커밋도 발송도 안 됩니다.

### B4. 시세 조회 실패가 정상값으로 위장
```python
if price is None:
    price = avg_price      # 삭제됨 → 수익률 0.0% 로 표시되던 원인
```
**수정**: 실패는 `ok: False` 로 유지, 화면에 "조회실패 — 값 미표시".

### B5. 요일·정렬·계산을 모델이 담당
지난 산출물에서 날짜 5건 요일 전수 오답, "강세 섹터" 칸에 -2.34%,
USD/KRW 변동을 "-1.03원"으로 표기 (실제 -15.12원 / -1.03%).

**수정**: 요일은 `fmt_date_label()`, 업종 강약은 부호로 강제 분리,
등락·이격도·52주 위치는 전부 파이썬 계산.

## 5. 검증 체크리스트

저장 직전 자동 실행. 하나라도 걸리면 파일을 쓰지 않습니다.

1. DOCTYPE 존재, `</head>` `</body>` `</html>` 존재, `</html>` 로 종료
2. `<div>` 여닫기 개수 일치
3. 분량 3,000~60,000자
4. `[[` `]]` `{{` `{%` `None` `NaN` `undefined` 미포함
5. 투자 지시 표현 미포함 ("매도 권고", "차감 권고" 등 8종)
6. 모든 날짜의 요일 표기가 실제 요일과 일치 (연도 있는/없는 형식 둘 다)
7. "강세 업종" 칸 전부 양수, "약세 업종" 칸 전부 음수
8. 헤더 날짜 라벨이 수집 메타와 일치
9. KOSPI·S&P500·USD/KRW 종가가 수집값 그대로 문서에 존재
10. KOSPI 등락률이 문서 내에서 서로 충돌하지 않음
11. 헤드라인 70자 이하
12. 수급 조회 실패 상태인데 금액이 표시되면 실패

**과거 실제 사고 7종 검출 테스트: 7/7 검출.**

단독 실행:
```bash
python generate_dashboard.py --validate index.html
python generate_dashboard.py --validate index.html data.json   # 수치 대조까지
```

## 6. 적용 절차

1. 위 5개 파일을 레포 루트에 덮어씁니다. 기존 프롬프트 템플릿 2개는 삭제.
2. GitHub Secrets 추가:
   - `TELEGRAM_BOT_TOKEN` — @BotFather 에서 봇 생성 후 발급
   - `TELEGRAM_CHAT_ID` — 봇에게 메시지 한 번 보낸 뒤
     `https://api.telegram.org/bot<TOKEN>/getUpdates` 에서 확인
   - 기존 `NAVER_EMAIL`, `NAVER_PASSWORD`, `PORTFOLIO_SHEET_ID`, `GEMINI_API_KEY` 는 삭제 가능
3. (선택) Repository variables 에 `DASHBOARD_URL` — GitHub Pages 주소.
   설정하면 텔레그램 요약 하단에 링크가 붙습니다.
4. `workflow_dispatch` 로 수동 1회 실행 후 로그의 `stop_reason` 과 `LLM hop` 줄을 확인합니다.

## 7. 실행 전 확인이 필요한 것

- **pykrx**: 이 환경에서 KRX 실호출을 검증하지 못했습니다. 1.2.8 임포트 시
  `KRX_ID / KRX_PW 환경변수 없음` 경고가 출력됩니다. 수급·업종 조회가 실패하면
  해당 섹션은 **표시되지 않고** 나머지는 정상 발행됩니다(가짜 숫자를 넣지 않습니다).
  첫 실행 로그에서 `OK 한국 수급` / `OK 섹터` 두 줄을 확인해 주세요.
- **Gemini 모드 제거**: `API_MODE` 분기를 들어냈습니다. 필요하면 되살립니다.
- **토요일·월요일 발행**: 스케줄은 매일 그대로입니다. KST 일요일·월요일 아침은
  직전 금요일 종가가 반복됩니다. 주 5회로 줄이려면 cron을 `50 20 * * 0-4` 로
  바꾸면 KST 월~금 발행이 됩니다.
